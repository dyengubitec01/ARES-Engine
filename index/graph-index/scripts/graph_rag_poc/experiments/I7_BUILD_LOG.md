# I-7 (K²RAG Corpus Pre-Summarization) 빌드 이력

**날짜**: 2026-06-04
**기법**: I-7 Corpus Pre-Summarization (K²RAG, ICONIP 2025) — **옵션 2 (압축 충실 테스트)**
**목적**: lazy 그래프(구조)는 유지하되, lazy가 생략한 **엔티티/커뮤니티 "설명"** 을 채워넣는다.
설명 생성 입력을 줄이기 위해 **청크 압축(K²RAG)** 을 적용하고, **압축본 설명 vs full 설명**을 비교해
"우리 문서(한국어·표·OCR)에서 압축이 설명의 핵심 사실을 죽이는가"를 직접 측정한다. (additive — 원본 청크 유지)

## ⚠️ 엔티티 수 인지 (사용자 명시 요청으로 기록)

- gliner2 **원본 엔티티 = 1,164개**. 정제(1글자·숫자 제거, 조사변형 병합) 후 **1,033개**.
- **이번 설명 생성은 그 중 281개(band 2~30)만** + 커뮤니티 11개 = **292콜**. 1,164개 전부가 아님 — 의식적 선택.
- 드롭 내역:
  - **연결청크 ≤1개: 718개 드롭** — 설명이 청크 1개 재진술에 그쳐 라우팅 가치 0 + 노이즈.
  - **연결청크 ≥31개: 34개 드롭** — `Autonova`(792청크)처럼 코퍼스 전체를 가리켜 변별력 0.
- **확장 레버**(원하면): 하한을 1로 내리면 +718콜(~30분), 상한을 50으로 올리면 +~22콜.

## 빌드 설계

1. **그룹 압축**: 청크를 위치순 ~10개씩 묶어(~100그룹) LLM으로 약 1/9(~89%) 압축. 고유명사·숫자·날짜·관계 보존 지시.
2. **설명 생성 ×2** (동일 청크집합 기준, 공정 A/B):
   - (압축본) 엔티티가 속한 압축 그룹 텍스트로 설명 생성
   - (full 대조군) 동일 엔티티의 원본 청크로 설명 생성
3. **저장**: 설명 = pseudo-chunk(엔티티 ≥210000 / 커뮤니티 ≥200000) additive 레이어. lazy 그래프·원본 청크 불변.

## 후속 측정

- A. **압축 vs full 설명 품질 비교** (judge ~50쌍) → 핵심 질문 답: 압축이 사실을 죽이나?
- B. (선택) **다운스트림 QA** 3트랙: baseline / 라우팅 전용 / 라우팅+생성.

## 결과 (2026-06-04, 확정)

**빌드 검증 (압축 vs full 설명, n=281)**: 압축이 설명을 죽이진 않음 — full 대비 사실토큰 retention 평균 69%(상당수는 손실 아닌 치환). 단 **cross-entity conflation 오류 발견**(예: Maps 자회사 설명에 Vision의 센서퓨전 사실 혼입 — 같은 압축 윈도우의 타 엔티티 사실이 새어듦).

**다운스트림 QA (27_i7route, full 설명층, N=3 결정론 ±0.000)**:

| track | judge | recall | keyword | 환각/40 |
|---|---|---|---|---|
| lazy_qt (baseline) | 0.836 | 0.808 | 0.863 | 10 |
| i7_route (라우팅 전용) | 0.812 (**−0.023**) | 0.897 (+0.089) | 0.798 | 8 |
| i7_gen (라우팅+생성) | 0.847 (**+0.012**) | 0.897 (+0.089) | 0.854 | 12 |

**판정: ❌ 기각.** recall +0.089는 R-5 수준 도달이나 **볼륨발**이라 답변으로 전환 안 됨(route는 distractor로 judge 악화). gen은 +0.012뿐인데 환각 증가(conflation 누출). **R-5에 모든 축 dominated**(같은 recall, judge 더 낮음, 환각 더 많음). I-3/I-5/I-6에 이은 "설명/요약 레이어 = 손해" 4번째 확증. 압축본 다운스트림·관계층은 미추진(full도 실패 + 관계는 환각 위험 최대).
